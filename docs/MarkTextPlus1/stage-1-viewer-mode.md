# Stage 1: Viewer Mode and document safety

Date: **23 October 2026**. Starting checkout: `214a9aad84b19a1d1cdea2b71668861ba99b1675`, branch `feature/marktext-plus-one`. Requirements: [README](README.md), [specification](specs.md), [Stage 0 acceptance matrix](baseline-feature-matrix.md#stage-1-acceptance-and-readiness) and the approved [Windows runner investigation](ui-test-investigation.md).

The interface continues to call Viewer Mode **Reading Mode**, using the existing translations. It extends the existing per-document `readOnly` state. No new permission model, split view, toolbar, branding, packaging, dependency changes or Git commit are included.

## Resulting behavior

- Raw Markdown source view stays mounted when locking or unlocking. CodeMirror becomes selectable and read-only, with native input protection and a `beforeChange` guard against programmatic text mutations. App command dispatch, formatting, insertion, replacement, clipboard paste and undo/redo handlers reject mutations while locked or transitioning.
- Find, next/previous match, selection, copying, scrolling and outline navigation remain available. The existing Find UI is shared between Muya and CodeMirror; replacement remains unavailable while locked. Source search uses the installed CodeMirror search-cursor addon. Source clipboard actions use the visible source selection, rather than the hidden visual editor.
- A persistent document footer labels Reading Mode / Edit Mode and provides a translated, keyboard-accessible mode button. It stays available with the sidebar and tabs hidden, under native/custom title bars, and uses existing theme variables. Focus returns to the control after its asynchronous transition.
- Source changes update document state on content-change events. Caret movement no longer submits content. The existing active-editor flush runs before locking; source handles that flush as well as save, tab-switch and close paths. The hidden Muya instance cannot overwrite active source content.
- Locking cancels scheduled autosave. Dirty content stays in memory. **Unlocking alone does not schedule a save**; explicit Save or a subsequent actual edit can save. This follows the Stage 1 instruction that unlocking must not silently save; it is more conservative than interpreting specification RO-03's “autosave resume only after an explicit unlock” as “save immediately on unlock.” Existing main-process lock epochs, queued-write coordination, atomic writes and close confirmation remain in place.
- CodeMirror's history remains per document and survives lock/unlock. Returning to Muya retains the existing single source-handoff undo boundary. Source dirty-state tracking now compares against saved text, including save acknowledgements, so undo to saved content clears the dirty marker and a divergent re-edit remains dirty. Restored dirty buffers without a known saved checkpoint remain dirty until saved.
- `Preferences > General > Default mode for opened files` remains the first setting, with its existing explanation that new documents stay editable. The upstream default remains Edit Mode. Existing tabs, explicit CLI overrides and restored per-document modes retain their existing precedence.
- Sidebar implementation, folder browsing, resizing, persistence and the independent outline are unchanged. Menu availability now reapplies source-view restrictions after rebuilding a menu, preventing Focus/Typewriter items from becoming enabled when unlocking a source document.

## Manual verification for review

Use disposable documents. The checks below have **not** been performed manually by the agent.

1. From a normal VS Code PowerShell terminal at the repository root, run `pnpm run start` to preview the built application. If that terminal inherits `ELECTRON_RUN_AS_NODE=1`, first run `Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue` in that terminal only.
2. In Preferences > General, inspect “Default mode for opened files.” Verify Edit Mode remains the existing default unless you changed it. Choose Reading Mode; leave an already open editable tab untouched. Open a different existing Markdown file via File > Open, the sidebar, dropping the file on the window and a local Markdown link. Each newly opened existing document should show Reading Mode. New untitled/import-created buffers should stay editable. Test an existing Windows file association only if it already points to this checkout; this stage does not install/register one. Change the preference back and verify the reverse for future opens.
3. Press Ctrl+E in Reading Mode. Select text and copy it into an untitled VS Code buffer. Try Ctrl+V, Ctrl+X, Backspace, Delete, Ctrl+B, Ctrl+Z/Ctrl+Y, menu formatting/insertion and replacement. Try text drag/drop and a real Windows IME composition. The document must stay unchanged; Find, next/previous result, selection, scrolling and outline clicks should work. Repeat in visual mode, including clicking a task checkbox and trying table/image tools. Verify copied text corresponds to the current editor selection.
4. Enable autosave with a comfortably long delay (for example 5 seconds). Edit a disposable file, immediately enter Reading Mode, and wait longer than the delay. Check in VS Code that disk content stayed unchanged while the app retains its dirty text. Unlock, wait again, and verify no save. Undo/redo should still work. Explicit Ctrl+S, or another actual edit followed by the autosave delay, should save. For a locked dirty close, verify Cancel retains the window and explicit “Switch to Edit Mode and Save” writes only when chosen.
5. Hide tabs using View and hide the sidebar with Ctrl+J. Use Tab/Enter/Space to operate the footer mode control. Check both native and custom title styles (restart when requested), light/dark themes, 100% and 200% Windows scaling and Narrator. The textual status, focus ring and action must remain visible/readable and announced. Source layout must stay selected after lock/unlock.
6. Resize the sidebar; toggle it with Ctrl+J, View and the command palette. Browse folders, run folder search and use the independent outline with the sidebar hidden. Close/reopen with “restore all” and layout restoration enabled; verify width, visibility, document modes and files restore. For the pre-existing typewriter `fixme`, use a long editable document, enable Typewriter Mode, type in a middle paragraph, then disable it: caret should stay in view without jumping to the bottom.
7. For an independent byte/timestamp check, take this snapshot before opening a disposable file, perform no-edit mode/source transitions, close normally, then compare:

```powershell
$stage1File = 'C:\path\to\disposable.md'
$stage1Before = [pscustomobject]@{
  Hash = (Get-FileHash -LiteralPath $stage1File -Algorithm SHA256).Hash
  Length = (Get-Item -LiteralPath $stage1File).Length
  ModifiedTicks = (Get-Item -LiteralPath $stage1File).LastWriteTimeUtc.Ticks
}
# Open, inspect, change modes without edits, and close the file in MarkText.
$stage1After = [pscustomobject]@{
  Hash = (Get-FileHash -LiteralPath $stage1File -Algorithm SHA256).Hash
  Length = (Get-Item -LiteralPath $stage1File).Length
  ModifiedTicks = (Get-Item -LiteralPath $stage1File).LastWriteTimeUtc.Ticks
}
Compare-Object $stage1Before $stage1After -Property Hash, Length, ModifiedTicks
```

The comparison should print no differences. Repeat with VS Code's LF/CRLF and supported BOM encodings, saving the fixture **before** taking the initial snapshot.
